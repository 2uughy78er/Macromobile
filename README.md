# Image Macro — 노루팅 Android 이미지 매크로

ROOT 권한 없이 동작하는 **범용 이미지 기반 자동화 매크로** 안드로이드 앱입니다.

사용자가 직접 화면을 캡처해 버튼 이미지를 등록하면, 앱이 화면을 계속 분석해 그 이미지를
찾아내고 발견된 위치를 자동으로 터치합니다. 등록해 둔 **타겟 카드**가 화면에 나타나면
매크로를 즉시 멈춥니다.

> 이 저장소에는 **어떤 앱·게임의 이미지도, 매크로 순서도, 좌표도 들어 있지 않습니다.**
> 설치 직후 매크로 목록은 비어 있으며, 모든 이미지와 단계는 사용자가 직접 등록합니다.

## 주요 기능

**화면**
- MediaProjection 기반 화면 캡처 (ROOT·ADB 불필요)
- 최신 프레임 재사용으로 반복 캡처 비용 최소화
- 화면 해상도 자동 감지, 회전으로 크기가 바뀌면 안전하게 중단

**이미지**
- 현재 화면에서 드래그로 잘라 이미지 등록
- 갤러리 이미지에서 등록
- OpenCV 템플릿 매칭 (`TM_CCOEFF_NORMED`, 알파 마스크가 있으면 `TM_CCORR_NORMED` + mask)
- threshold, ROI, 클릭 오프셋 설정
- 해상도 자동 보정 (letterbox/pillarbox 여백 포함)
- 여러 템플릿 OR / AND / COUNT 판정
- 같은 템플릿 다중 검색 + 중복 제거(NMS)
- 배율별 템플릿 캐시

**자동화**
- 이미지 발견 후 터치 / 발견 대기 / 있으면 터치
- 목표 이미지가 나올 때까지(또는 사라질 때까지) 연타
- 좌표 터치, 스와이프, 키 이벤트(뒤로·홈·최근 앱 등)
- 텍스트 자동 입력 (접근성 `ACTION_SET_TEXT`, 실패 시 클립보드 붙여넣기)
- 온디바이스 OCR(ML Kit)로 화면 글자를 읽어 변수에 저장
- 런타임 변수 (`@변수명`, `@random`, `@randomnum:6` 등)

**타겟**
- 타겟 이미지 여러 개 등록, 타겟별 ROI·threshold
- ANY / ALL / COUNT 판정
- **타겟 발견 즉시 매크로 중지**
- 백그라운드 Target Monitor (매크로 단계와 별개로 상시 감시)
- 오탐 방지용 연속 N회 검출, 매칭 크기 제한
- Target Found 화면 + 발견 위치 표시 + 화면 저장

**실행**
- 시작 / 일시정지 / 재개 / 중지
- 반복 횟수 지정, 무한 반복
- 단계별 timeout 과 실패 정책(처음부터 다시 / 건너뛰기 / 중단)
- Foreground Service — 앱 UI 를 닫아도 계속 실행
- 실행 중 오버레이 컨트롤러 (다른 앱 위에 표시)
- 알림에서 바로 일시정지·중지

## 동작 원리

```
        [사용자]
           │  화면 캡처 → 버튼 영역 드래그 → 이미지 등록
           ▼
   ┌───────────────────┐
   │   매크로 (JSON)    │  단계 · 템플릿 · 타겟
   └─────────┬─────────┘
             │
             ▼
   ┌───────────────────────────────────────────────┐
   │              MacroForegroundService            │
   │                                                │
   │  ScreenCaptureManager ──► ScreenFrame          │
   │   (MediaProjection)          │                 │
   │                              ▼                 │
   │                      TemplateMatcher (OpenCV)  │
   │                              │                 │
   │            ┌─────────────────┴───────────┐     │
   │            ▼                             ▼     │
   │       MacroEngine                  TargetMonitor│
   │            │                             │     │
   │            ▼                             ▼     │
   │      StepExecutor                  타겟 발견?   │
   │            │                             │     │
   │            ▼                             ▼     │
   │     GestureController              STOP REQUEST│
   │     (AccessibilityService)                     │
   └────────────┬───────────────────────────────────┘
                ▼
          실제 화면 터치
```

핵심 규칙: **`MacroEngine` 은 어떤 앱이나 게임도 알지 못합니다.**
사용자가 만든 `MacroStep`, `Template`, `Target` 만 보고 동작합니다.

## GitHub Actions 로 APK 빌드하기

이 저장소는 **PC 에 Android Studio 를 설치하지 않고도** GitHub 에서 바로 APK 를 만들 수
있도록 구성되어 있습니다.

### 자동 빌드

`main` 을 포함한 모든 브랜치에 push 하면 워크플로가 자동으로 실행됩니다.

### 수동 빌드

1. GitHub 저장소 → **Actions** 탭
2. 왼쪽에서 **Build APK** 선택
3. 오른쪽 **Run workflow** → 브랜치 선택 → **Run workflow**

### APK 내려받기

빌드가 끝나면 (초록 체크 ✓) 해당 실행 페이지 맨 아래 **Artifacts** 에서 받습니다.

| 이름 | 설명 |
|---|---|
| `image-macro-debug-apk` | 디버그 빌드. 바로 설치해서 쓰면 됩니다. |
| `image-macro-release-apk` | 릴리스 빌드(기본은 서명 없음). |

> **APK 크기**: OpenCV 네이티브 라이브러리 때문에 APK 는 80MB 안팎입니다.
> 실제 기기가 쓰는 `arm64-v8a` / `armeabi-v7a` 두 ABI 만 담고 있습니다.
> 에뮬레이터에서 돌려보려면 `app/build.gradle.kts` 의 `abiFilters` 에 `"x86_64"` 를 추가하세요.

> **어떤 걸 받아야 하나요?** 그냥 써볼 거라면 **debug** 를 받으세요.
> debug APK 는 CI 가 자동으로 서명하므로 별도 설정 없이 설치됩니다.
> release APK 는 서명 키를 넣지 않으면 서명되지 않아 그대로는 설치되지 않습니다.

### 태그를 붙여 릴리스 만들기

```bash
git tag v1.0.0
git push origin v1.0.0
```

`v` 로 시작하는 태그를 올리면 GitHub Releases 에 APK 가 자동으로 첨부됩니다.

### 업데이트 설치와 서명 키

APK 를 새로 받아도 **앱을 지울 필요 없이 그냥 덮어쓰기 설치**하면 됩니다.
만들어 둔 매크로와 이미지는 그대로 남습니다.

이게 가능하려면 서명 키가 매번 같아야 합니다. 안드로이드는 서명이 다른 APK 의
덮어쓰기 설치를 거부하고 `패키지가 기존 패키지와 충돌하여 앱이 설치되지 않았습니다`
라는 오류를 냅니다. 그래서 debug 전용 고정 키를 `keystore/debug.keystore` 에 두고
저장소에 함께 넣어두었습니다.

이 키를 저장소에 두지 않으면 빌드할 때마다 안드로이드 빌드 도구가 임시 키를 새로
만들어 서명이 매번 달라집니다. 그러면 업데이트할 때마다 앱을 지웠다 깔아야 하고,
**그때마다 만들어 둔 매크로가 전부 사라집니다.**

debug 키는 보안 장치가 아니라 "같은 앱임을 알아보게 하는 표식"입니다. 비밀번호도
안드로이드 표준값(`android`)이라 숨길 것이 없습니다. 실제 배포용 서명은 아래처럼
CI 비밀값으로 따로 받습니다.

빌드 로그의 `Print debug APK signing fingerprint` 단계에서 서명 지문을 확인할 수
있습니다. 이전 빌드와 지문이 같으면 덮어쓰기 설치가 됩니다.

### release APK 에 서명하기 (선택)

서명된 release APK 가 필요하면 저장소 **Settings → Secrets and variables → Actions** 에
아래 값을 등록한 뒤, 워크플로의 빌드 단계에 환경변수로 넘기면 됩니다.

| 환경변수 | 뜻 |
|---|---|
| `MACRO_KEYSTORE_FILE` | keystore 파일 경로 |
| `MACRO_KEYSTORE_PASSWORD` | keystore 비밀번호 |
| `MACRO_KEY_ALIAS` | 키 별칭 |
| `MACRO_KEY_PASSWORD` | 키 비밀번호 |

`app/build.gradle.kts` 는 `MACRO_KEYSTORE_FILE` 이 비어 있으면 서명 설정을 건너뜁니다.
**keystore 파일과 비밀번호는 절대 저장소에 커밋하지 마세요.**

## 설치와 첫 실행

1. APK 를 기기에 옮겨 설치합니다 (출처를 알 수 없는 앱 설치 허용 필요).
2. 앱을 실행하면 알림 권한을 묻습니다 — 허용하는 편이 좋습니다(실행 상태 확인용).
3. 메인 화면에서 **권한 설정** 으로 들어갑니다.

### 필요한 권한

| 권한 | 왜 필요한가 | 필수 |
|---|---|---|
| **접근성 서비스** | 화면을 대신 터치·스와이프하고 텍스트를 입력 | 필수 |
| **화면 캡처(MediaProjection)** | 등록한 이미지를 화면에서 찾기 | 필수 |
| **다른 앱 위에 표시** | 실행 중 작은 컨트롤러 표시 | 선택 |
| **알림** | 실행 상태 표시 및 알림에서 제어 | 권장 |

접근성 설정 경로: **설정 → 접근성 → 설치된 서비스(또는 다운로드한 앱) → `Image Macro 자동 조작` → 사용**

> 화면 캡처 권한은 기기를 재시작하거나 권한을 취소하면 다시 허용해야 합니다.

## 사용 흐름

```
앱 설치
  ↓
접근성 권한 허용
  ↓
화면 캡처 권한 허용
  ↓
[새 매크로]
  ↓
[이미지 등록] → 현재 화면 캡처 → 버튼 영역 드래그 → 이름·threshold 입력 → 저장
  ↓
[단계 추가] → '이미지 발견 후 터치' 선택 → 방금 등록한 이미지 체크 → 저장
  ↓
필요한 만큼 단계 추가 (대기 / 텍스트 입력 / 스와이프 / 좌표 터치 …)
  ↓
[타겟 카드] → 원하는 카드 이미지 등록 → '타겟 감시 켜기'
  ↓
메인 화면 → [▶ 시작]
```

### 이미지를 등록할 때

**현재 화면 캡처** 를 누르면 앱이 5초 동안 자동으로 내려갑니다.
그 사이에 등록하려는 화면을 띄워두면, 5초 뒤 캡처가 끝나고 앱이 다시 올라옵니다.

캡처된 화면에서 **원하는 버튼 영역만** 손가락으로 드래그하세요.
선택 영역 밖은 어둡게 표시되고, 아래에 잘려나갈 부분의 미리보기가 나타납니다.

> 팁: 시간에 따라 변하는 부분(숫자, 애니메이션, 캐릭터)은 빼고,
> 항상 똑같이 보이는 부분만 감싸면 인식률이 훨씬 좋아집니다.

## 매크로 백업 — 내보내기 / 가져오기

공들여 만든 매크로를 잃지 않으려면 **백업 파일로 내보내두세요.**

- **내보내기**: 매크로 편집 화면 우측 상단 ⬆ 아이콘, 또는 "기본 정보"의 `백업 파일로 내보내기`
- **가져오기**: 매크로 목록 화면 우측 상단 ⬇ 아이콘

백업 파일(`이름.macro.zip`)에는 **단계·설정뿐 아니라 등록한 이미지까지** 함께 들어갑니다.
앱을 지웠다 다시 깔거나 기기를 바꿔도 이 파일 하나로 그대로 되살아납니다.

가져오기는 언제나 **새 매크로로 추가**되므로 기존 매크로를 덮어쓰지 않습니다.

> 앱 데이터는 안드로이드 내부 저장소에 있어 루팅 없이는 밖에서 꺼낼 수 없습니다.
> 앱을 삭제하면 매크로도 함께 사라지므로, 중요한 매크로는 만들자마자 내보내두는 편이 안전합니다.

## 지원하는 동작(Action)

| 동작 | 하는 일 |
|---|---|
| `WAIT` | 정해진 시간만큼 대기 |
| `TAP` | 지정한 좌표를 한 번 터치 |
| `WAIT_FOR_IMAGE` | 이미지가 나타날 때까지 대기(터치하지 않음) |
| `WAIT_AND_TAP` | 이미지가 나타나면 **발견된 그 위치** 를 터치 |
| `TAP_IF_FOUND` | 짧게 확인해 있으면 터치, 없으면 그냥 통과 (팝업 처리용) |
| `TAP_UNTIL_IMAGE` | 목표 이미지가 나올 때까지 지정 위치를 연타 |
| `TAP_UNTIL_IMAGE_DISAPPEARS` | 지정 이미지가 사라질 때까지 연타 |
| `SWIPE` | 두 지점 사이를 밀어 넘김 |
| `TEXT_INPUT` | 입력창에 텍스트 자동 입력 |
| `KEY_EVENT` | 뒤로 / 홈 / 최근 앱 / 알림창 / 화면 잠금 |
| `SCREENSHOT` | 현재 화면을 파일로 저장 |
| `OCR` | 지정 영역의 글자를 읽어 변수에 저장 |
| `TARGET_CHECK` | 등록한 타겟이 화면에 있는지 판정 |
| `STOP_MACRO` | 여기서 매크로 종료 |

### 단계 실패 정책 (`On Timeout`)

| 값 | 동작 |
|---|---|
| `RESTART` | 이번 반복을 버리고 매크로를 처음부터 다시 |
| `SKIP` | 이 단계를 건너뛰고 다음으로 |
| `STOP` | 매크로 전체 중단 |

## 해상도 자동 보정

매크로를 만든 기기와 실행하는 기기의 해상도가 달라도 그대로 동작합니다.

배율은 가로·세로 중 **작은 쪽** 을 씁니다. 화면 비율이 다르면 남는 부분은
가운데 정렬 여백(letterbox / pillarbox)으로 처리합니다.

```
scale   = min(화면너비 / 기준너비, 화면높이 / 기준높이)
offsetX = (화면너비 - 기준너비 × scale) / 2
offsetY = (화면높이 - 기준높이 × scale) / 2

화면좌표 = 기준좌표 × scale + offset
```

예) 기준 `720×1280` 매크로를 `1080×2400` 화면에서 실행

| 항목 | 값 |
|---|---|
| scale | `min(1080/720, 2400/1280)` = `min(1.5, 1.875)` = **1.5** |
| offsetX | `(1080 − 720×1.5) / 2` = **0** |
| offsetY | `(2400 − 1280×1.5) / 2` = **240** |

기준 좌표 `(100, 200)` → 화면 좌표 `(150, 540)`

클릭 오프셋 같은 **거리** 값에는 배율만 곱하고 여백은 더하지 않습니다.

템플릿 이미지도 같은 규칙으로 리사이즈된 뒤 매칭에 쓰이고, 배율별 결과는 캐시됩니다.

## 매크로 변수와 텍스트 입력

텍스트 입력 단계의 값에 아래 표기를 쓸 수 있습니다.

| 표기 | 결과 |
|---|---|
| `@변수명` | 저장된 변수 값 (없으면 표기를 그대로 둠) |
| `@random` | 소문자 4자 + 숫자 4자 |
| `@random:8` | 소문자·숫자를 섞은 8자 |
| `@randomstr:6` | 소문자 6자 |
| `@randomnum:6` | 숫자 6자 |
| `@@` | 문자 `@` |

한 문장에 여러 번 써도 모두 치환됩니다. 예: `user@random@@example.com`

변수는 **매크로 실행 시작 시(그리고 반복마다) 초기화**됩니다.

### OCR 로 변수 채우기

`OCR` 단계는 지정한 ROI 의 글자를 읽어 변수에 담습니다.

- `저장할 변수 이름` — 예: `code`
- `허용할 문자` — 예: `0123456789ABCDEF` (비우면 제한 없음)
- `기대하는 글자 수` — 예: `6` (0 이면 확인 안 함)
- `한국어 인식기 사용` — 끄면 영문·숫자 인식기(짧은 코드에 더 정확)

이후 텍스트 입력 단계에서 `@code` 로 꺼내 씁니다.

### 텍스트 입력이 실패한다면

1순위로 접근성 `ACTION_SET_TEXT`, 실패하면 클립보드 붙여넣기를 시도합니다.
두 방법 모두 대상 앱이 입력창을 접근성 노드로 노출해야 동작합니다.
자체 렌더링 입력창을 쓰는 일부 앱에서는 자동 입력이 불가능하며, 앱이 그 사실을 알려줍니다.

> 텍스트 입력 단계 앞에 **입력창을 터치하는 단계**를 반드시 넣으세요.

## 타겟 카드와 즉시 중지

타겟은 "이게 화면에 나오면 즉시 멈춰라" 를 뜻합니다.

### 등록 방법 두 가지

- **A. 현재 화면에서** — 화면 캡처 → 카드 영역 드래그 → 저장
- **B. 갤러리에서** — 이미지 선택 → 영역 드래그 → 저장

### 판정 방식

| 모드 | 성공 조건 |
|---|---|
| `ANY` | 등록한 타겟 중 **하나라도** 발견 |
| `ALL` | 등록한 타겟 **전부** 발견 |
| `COUNT` | **N개 이상** 발견 |

### 두 가지 감지 경로

1. **`TARGET_CHECK` 단계** — 매크로 흐름의 정해진 지점(보통 결과 화면)에서 판정
2. **Target Monitor** — 매크로 단계와 **별개로** 화면을 계속 감시

Monitor 를 켜두면 흐름 어디에서 타겟이 나타나든 놓치지 않습니다.

### 타겟을 찾은 순간

1. 진행 중이던 반복 작업 중단
2. 추가 터치 금지
3. 대기 작업 취소
4. 상태를 `TARGET_FOUND` 로 변경
5. 화면 저장 (설정에 따라)
6. 찾은 타겟 이름과 유사도 표시
7. 사용자가 결정할 때까지 대기

### 오탐 줄이기

| 설정 | 효과 |
|---|---|
| `threshold` 를 높임 (예: 0.92) | 더 정확히 같은 그림만 인정 |
| `ROI` 지정 | 카드가 나올 영역만 검사 |
| `연속 검출 횟수` = 2 이상 | 짧은 간격으로 N회 연속 보일 때만 중지 |
| 매칭 크기 제한 | 지나치게 작거나 큰 매칭은 무시 |

`연속 검출 횟수 = 1` 이면 한 번만 보여도 즉시 중지합니다(즉시 중지 모드).

## 성능과 배터리

화면 캡처와 이미지 매칭은 CPU 를 많이 씁니다. 다음을 조절하세요.

| 설정 | 권장 |
|---|---|
| **화면 검사 간격** | 300~500ms. 200ms 이하는 배터리 소모가 급격히 늘어납니다. |
| **매칭 해상도** | 잘 찾는다면 75% 나 50% 로 낮추면 훨씬 빠릅니다. |
| **ROI** | 가장 효과가 큽니다. 화면 전체 대신 나올 영역만 검사하세요. |
| **Target Monitor** | 필요 없으면 끄세요. 별도 스레드에서 계속 화면을 봅니다. |

그 밖에 앱이 자동으로 하는 최적화:
- 한 프레임의 Bitmap→Mat 변환 결과를 그 프레임의 모든 템플릿이 공유
- 배율별 템플릿 캐시(LRU)
- 최신 프레임 재사용(좌표 터치 등 최신 화면이 꼭 필요 없는 경우)
- 모든 매칭은 백그라운드 스레드에서 수행 (UI 스레드에서 OpenCV 작업 없음)

## 문제 해결

**이미지를 못 찾습니다**
- threshold 를 낮춰보세요 (0.85 → 0.75)
- 매칭 해상도를 원본(100%)으로 되돌려보세요
- 설정에서 **실패한 화면 저장** 을 켜고, 실제로 어떤 화면이었는지 확인하세요
- 등록한 이미지에 시간에 따라 변하는 부분이 들어가지 않았는지 보세요

**엉뚱한 곳을 누릅니다**
- threshold 를 올리세요 (0.85 → 0.92)
- ROI 를 지정해 검색 범위를 좁히세요
- 클릭 오프셋으로 실제 버튼 위치를 맞추세요

**"접근성 서비스가 연결되어 있지 않습니다"**
- 설정 → 접근성에서 서비스를 켜세요
- 배터리 최적화가 서비스를 끄는 경우가 있습니다. 이 앱을 최적화 예외로 두세요

**"화면 캡처 권한이 만료되었습니다"**
- 기기 재시작이나 권한 취소 후에 나타납니다. 다시 허용해주세요

**"화면 크기가 바뀌었습니다"**
- 실행 중 화면이 회전하면 좌표 보정이 어긋나므로 안전하게 중단합니다
- 화면 방향을 되돌리고 다시 시작하세요

**텍스트가 입력되지 않습니다**
- 입력창을 터치하는 단계를 앞에 넣으세요
- 대상 앱이 입력창을 접근성 노드로 노출하지 않으면 자동 입력이 불가능합니다

**매크로가 멈추지 않습니다**
- 알림의 **중지** 버튼, 또는 오버레이 컨트롤러의 ■ 버튼을 쓰세요
- 접근성 서비스를 끄면 즉시 모든 터치가 중단됩니다

## 개인정보와 권한

- **네트워크 권한을 요청하지 않습니다.** 화면 이미지는 기기 밖으로 나가지 않습니다.
- 화면 캡처와 이미지 분석, OCR 은 **모두 기기 안에서** 이뤄집니다.
- 등록한 이미지와 매크로는 앱 내부 저장소에만 저장되며, 앱을 지우면 함께 삭제됩니다.
- ROOT 권한을 요구하지 않으며, 사용하지도 않습니다.
- 접근성 서비스는 매크로가 실행 중일 때만 화면을 조작합니다.

## 알려진 한계

- **DRM 보호 화면**(일부 영상 앱, 금융 앱의 보안 화면)은 MediaProjection 으로 캡처되지 않아
  검은 화면으로 나옵니다.
- 일부 앱은 접근성 제스처를 차단합니다. 이 경우 터치가 전달되지 않습니다.
- 입력창을 접근성 노드로 노출하지 않는 앱에서는 텍스트 자동 입력이 불가능합니다.
- 임의의 KeyEvent 주입은 노루팅 환경에서 불가능합니다. 전역 동작(뒤로·홈 등)만 지원합니다.
- 실행 중 화면 회전은 좌표 보정을 깨뜨리므로 매크로를 안전하게 중단합니다.
- 화면 캡처 권한은 기기 재시작 후 다시 허용해야 합니다.
